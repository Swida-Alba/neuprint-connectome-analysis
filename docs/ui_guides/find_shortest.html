Shortest Paths

Find only the shortest (minimum hop-count) paths between source and target neuron groups. For every reachable pair, all tied shortest paths are kept. Discovery starts from target neurons and follows incoming branches to enrolled source bodyIds. Runs on the full Find All Paths pipeline (discovery, enrichment, outputs, visualization) with shortest-only enumeration.

Quick start

  1. Add Source Neurons (e.g. aMe12, aMe10).
  2. Add Target Neurons (e.g. PPL101, DN1p).
  3. Click Shortest Paths.
Use a small source set: if Source Neurons contains more than one type/name query, the page warns that each query can expand to many source bodyIds and enlarge the target-rooted search. Prefer one source type or query. Use explicit bodyIds with bodyId output enabled when exact source-target pairs are needed.

All-neurons queries (all_neurons)

Typing the special chip all_neurons as the source or target loads the full (typed) neuron set on that side, so the run fetches every adjacent neuron at the given thresholds (Min Synapse Count):

  • all_neurons replaces every other chip in the same input.
  • Source and target cannot both be all_neurons.
  • An all_neurons side forces Max Intermediate Layers = 0 (direct connections only). With shortest-path semantics this reports every direct edge (one hop) from or to the other side at the given thresholds.
Script/API parity: the backend (FindNeuronConnection.InitializeNeuronInfo) enforces the same rules, so passing sourceNeurons=['all_neurons'] in code behaves identically. All typed neurons are loaded from local data (works offline with Cache Only).

Depth cap (default: 5 intermediate layers)

  • Max Intermediate Layers (optional) = 0 means direct connections only. For a positive value M, paths are capped at M + 1 hops.
  • The tab default is 5 (deeper than the Complete Paths default of 2), because shortest-path searches typically target deeper routes. Increase it further when a query needs deeper intermediate layers. Backward discovery continues until the enrolled source bodyIds are reached or this bound is hit.
  • If the bound truncates an active frontier, results are shortest only within the explored, threshold-filtered graph. A path at that boundary is a constrained solution, not proof of a globally shortest route.

Score formulas

Every connection and path is scored on the thresholded graph D_t (edges with weight ≥ Min Synapse Count). Ratios use the global total incoming weight so the denominator reflects the whole dataset, not just the query:

ScoreFormulaRange
connection_ratiow_ij / Σ_k w_kj over D_t (edge weight ÷ total input to the post neuron)0–1
traversal_probabilitymin(1.0, connection_ratio / 0.3) (30% input = maximal)0–1
block_probability1 − traversal_probability0–1
path_probΠ of the edge traversal probabilities over the path0–1
min_weightweakest edge synapse count along the path (the bottleneck)integer
min_ratiosmallest edge connection ratio along the path0–1

At the type level the aggregate probabilities are computed from the deduplicated bodyId-level pairs of D_t: type-level traversal probability uses the product method by default (1 − Π(1 − p_pair)), which models parallel channels. Full derivations live in Score Calculation Guide.

No algorithm selector: shortest enumeration is a backward-BFS distance pass plus a guided DFS over the shortest-path DAG — polynomial in graph size. The combinatorial path explosion of Find All Paths does not exist here.
The Edge Budget is off in shortest mode. Its purpose (bounding the exponential path count) does not apply to shortest enumeration, and flooring (a threshold raise) preserves pair reachability but not shortest distance — a dropped weak edge can silently inflate a reported distance. The tab disables the Edge Budget input in shortest mode; API callers passing graph_edge_limit_bodyid get the full un-floored graph here.

BodyId enrollment

When type-level output is used, several exact bodyId pairs can collapse to one type sequence. The run records this caveat in user_warning_notes.txt. Check the root-level source_neurons.csv (isInPath) and target_neurons.csv (Checked, Layer). Run Shortest Paths with Skip BodyId off for specific bodyId pairs, or use Complete Paths to enumerate all paths under a chosen depth.

Advanced options

  • Keywords to Exclude from Paths — same semantics as Find All Paths.
  • Custom source/target names, Cache Only (Offline), Save Folder Name.
  • Hemisphere options: separate L/R labels, hemisphere filter, keep conserved edges, symmetry analysis — see Hemisphere analysis.
  • Find Reciprocal Connections — enriches the path graph with direct connections among its nodes.

Lmax records the exact bound used for the run; L99 is simply a practical high bound. With Skip BodyId off, bodyId-level tables (data_details/connection_info_bodyId.csv and ..._allpaths_bodyId_paths.csv) are written alongside the type-level ones. The full reference is in docs/OUTPUT_FILES.md.

Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run.
