3D Skeleton (plot3dSkeleton)

The 3D Skeleton tab renders neuron morphology, synapses and brain region meshes from any configured dataset into an interactive HTML scene. It runs VisualizeSkeleton.plot_neurons() in the background. For pathway graphs see the separate Network guide.

Quick start

  1. In the Layer Structure tree, three layer rows are ready by default — add neurons to them, or click Add Layer for more rows.
  2. Pick the dataset; keep Brain Mesh = template. ROI meshes are optional and start unselected.
  3. Click Generate 3D Skeleton.

Inputs & examples - the layer tree

The tree mirrors the script's nested-list layer model: each row is one layer and may hold several neurons (type, instance, bodyId or regex). Drag a row to reorder layers; drag a neuron chip onto another row to regroup it. Optional layer names feed the legend (unnamed layers are auto-named): the per-row name input is collapsed behind the small edit button so the rows stay compact.

Neuron valueMeaning

aMe12_RHemisphere-specific instance

The Match by mode (exact / starts with / contains / ends with / regex) converts every neuron in the tree into a regex pattern, and the Search Columns selector (auto / type / instance / bodyId) scopes name resolution — the same neuron-search backend as Find All Paths. Upload formats for neuron lists are documented in Input File Formats.

Layer editor modes

Three segmented buttons on one row (Standard, Advanced, File upload) pick how the neuron layers and their colors are defined, and a Synapse Mode box plus Synapse Threshold sit directly below them. Only Standard mode uses the on-screen color palette editors (Neuron Colors / Synapse Colors / ROI Colors); the other two modes take colors from the in-file settings.

  • Standard — the classic drag-and-drop layer rows (add neurons to a row, drag rows to reorder, drag chips between rows). An Export CSV button writes the current order to the layer-map CSV format (layer,neuron). The color palette editors are shown here.
  • Advanced — selecting it shows the editable layer editor table directly (it is not collapsed). Each row's Layer cell is a selection box that starts at 1 for a new table and only offers the currently available layers (so layer 2 is never offered unless layer 1 is in use). Existing 0-based CSVs remain supported, but every used layer number must be continuous. The colour columns follow the synapse mode: Synapse color for synapse, or Pre-synaptic + Post-synaptic colors for pre-post sites (and the exported/uploaded CSV matches that same column set). The single-color picker (alpha + Bokeh palette) is opened from a color cell's picker button or the palette button beside each colour input in the Add Row form. Empty color cells display (auto). The See available neurons viewer appends one row per selected entry and assigns the whole viewer-selection batch to the next layer; the Add Row neuron field also provides dataset-aware suggestions. Rows are auto-saved to disk as you edit; use Export CSV to download, or Upload CSV to load a file into the table. The color palette editors are hidden (colors come from the file).
  • File upload — upload a custom-layer CSV directly. Its color columns are used as-is (no editable table, no color palette editors).

The same custom-layer CSV can also be produced/edited by hand. It has a layer column (numbers may start at 0 or 1; the lowest value is treated as the first layer) and a neuron column (any legal query name, the legacy id_type_instance name also works). Optional color columns:

ColumnMeaning
colorPer-neuron display color. rgba(...) overrides the global Neuron Opacity; rgb(...) inherits it.
synapse_colorColor of the inter-layer (connector) synapses whose pre-synaptic site is this neuron.
pre_synaptic_colorColor of this neuron's pre-synaptic sites (only used by the pre/post mode).

Hemisphere analysis

The Hemisphere selector (next to Search Columns) restricts the plotted neurons to one side:

  • both (default): all neurons.
  • left: only left-hemisphere neurons.
  • right: only right-hemisphere neurons.

Hemisphere assignment is automatic per neuron: the Soma side / hemisphere column wins when present, otherwise the instance suffix (_R → right, _L → left). Neurons with neither are unclassified (U) and are always included in every option — so datasets whose neurons lack hemisphere notation (e.g. some non-NeuPrint tables) are never silently dropped.

Manual suffix search still works — a chip like aMe12_R or .*_R selects one side per type; the Hemisphere selector applies the same rule to every neuron automatically, including those without a suffix.

Options

The form is organized into four independent blocks, each with its own card: General Appearance, Neuron Colors, Synapse Colors and Brain Region ROIs.

General Appearance

  • Skeleton Mode: tube (detailed) or line (fast).
  • Neuron Legend Mode: layer, type, tree, or single. ROI meshes always keep independent legend entries and rank after every neuron entry (brain mesh, then VNC mesh, last).
  • Expandable legend (tree): the exported interactive HTML replaces the flat legend with a collapsible panel at the original legend position (top-right). Each type row shows a color swatch and neuron count and expands to per-neuron bodyId rows; toggling a type hides its skeleton and pre/post site traces, individual neurons toggle separately, and synapse/mesh rows sit below the types (meshes last). Static exports keep the plain type-level legend.
  • Background: white or black. The default neuron palette follows it — Category10 on white, Set3 on black — until you pick a palette manually.
  • Theme switch in the exported HTML: the main viewer HTML (and its _simplified.html copy) carries a floating 🌙/☀️ button (top-right, or press T) that flips the page between light and dark for viewing — background, legend, dropdown/hint text, and the auto brain/VNC mesh color all follow. It always opens with the configured Background; static exports (view PNGs, per-neuron files, video) keep the fixed background, and neuron/synapse colors stay as generated.
  • Brain Mesh: template, whole, or none; VNC Mesh toggle for male-cns/manc.

Neuron Colors

  • Neuron Opacity: global fallback opacity for skeletons (0=invisible, 1=solid).
  • Full bokeh palette catalog with custom editing. Preset palettes are picked from a full-width name dropdown; every option in the dropdown list shows the palette name with a strip preview filling the row to its right (discrete palettes as distinct color blocks, continuous palettes as a smooth gradient), so palettes are visible before selection. The selected palette shows in the interactive preview row, where swatches can be dragged to reorder discrete palettes, a live range slider selects part of the palette, and reset restores the original order and full range.
  • Custom colors: starts empty — no preset palette is shown until colors are added. Use the shared Pick color popup, free-form color formats, or individual swatches of any Bokeh palette (choose the palette in the dropdown, click a swatch to select it, then press Add color). The popup's alpha slider uses 0.05 steps and only embeds alpha when Override alpha is checked; otherwise the renderer's global Neuron Opacity is inherited. Added colors appear in the horizontal preview bar, where they can be dragged to reorder or removed with their red cross.
  • Default follows the background (Category10 / Set3) until a palette is picked manually.

Synapse Colors

  • Synapse Mode: an outlined dropdown — synapse (paired markers between consecutive layers), pre-post sites (the input/output sites of the queried neurons), or skip (hide markers). The cutoff Min Synapse Count sits beside it.
  • Synapse Shape (synapse mode): cone / scatter / sphere / tetrahedron.
  • Pre/post shape (pre-post sites mode): solid (post/input sites as spheres, pre/output as cones) or scatter (post/input as circles, pre/output as squares).
  • Synapse Threshold (formerly Min Synapse Count): minimum synapse weight for a marker to be shown; in pre-post site mode only sites whose connection with a neighbour meets this threshold are shown. It sits to the right of the Synapse Mode box, below the layer-editor buttons.
  • Synapse Size (a fold of the real pre→post distance: real = 1x; any number or Nx real can be typed). In pre/post-site mode every site is uniform and uses the full mean real connector distance as its glyph size because each sphere/cone is centered on its own pre- or post-synaptic site; a one-layer view estimates it from sampled upstream/downstream pairs. Uniform Synapse Size applies to paired markers, and Opacity remains global.
  • pre-post (Pre/post-synaptic site mode): instead of the paired synapses between adjacent layers, this renders the pre- and post-synaptic sites of every queried neuron. Post-synaptic (input) sites draw as spheres, pre-synaptic (output) sites as cones (or circle/square scatter markers, see Pre/post shape), both colored by the neuron's layer and given separate pre <layer> / post <layer> legends. It is not a paired-synapse view: the partner is not restricted to the adjacent layer. An orange in-page banner and a note in user_warning_notes.txt flag its behavior.

Brain region ROIs

  • The Mesh ROIs suggestions start with the complete dataset primary-ROI list from datasets/<dataset>/*metadata*. Type all to request every locally available ROI.
  • Include L/R variants keeps explicit (L)/(R) entries in the primary list; otherwise bilateral pairs are shown once.
  • Include sub-primary ROIs appends non-primary entries to the primary list.
  • No ROI mesh is selected by default.
  • Mesh ROIs: presets or regex (ME.*, all, primary).
  • ROI Colors: Auto gray, or any palette assigned in its exact displayed order; custom and discrete-palette reordering is preserved.
  • Each resolved ROI mesh, including bilateral expansions, is a separate trace and legend entry.
  • ROI Mesh Opacity.
  • Brain Mesh Color: swatch picker with custom color.

Advanced

  • Cache Neurons/Synapses: faster repeat renders.
  • Smooth Skeleton, Show Soma, Show Connectors.
  • Simplification Method (NeuPrint tube mode): fast is the default direct path with render-time mesh simplification. fine is the FAFB-style transform rebuilt from the shared raw .swc.zst cache; fine meshes are not persisted. artistic uses vertex-cluster mesh decimation. All methods use batched parallel online skeleton fetching across layers. The selector is available for NeuPrint and FlyWire/FAFB tube renders; line mode bypasses it.
  • Mesh Simplification: defaults to 90% faces removed for fast and 95% for fine/artistic in this tab, including FAFB/FlyWire; line mode does not apply mesh simplification.
  • Export Method: webdriver (fast, needs Chrome 109+) or kaleido (stable fallback). Export Scale and Export Views.
  • Individual Profiles: PDF/PPTX per neuron, with images per page and camera views.
  • Rotating Video / GIF: fps, degrees per frame, rotation axis, GIF scale.

Output

One timestamped folder per run, named after the dataset abbreviation and the layer names:

{output_dir}/plot-3d_MCNS_aMe12_SMP238_PPL101_20260815_151243/
    aMe12_SMP238_PPL101.html            - interactive 3D scene
    aMe12_SMP238_PPL101_neuron_info.csv - merged neuron metadata with a
                                          numeric viz_layer column before
                                          bodyId
    viz_layer_info.csv                  - reusable input layer assignments and
                                          readable colors; only the active
                                          synapse color family is populated
    parameters.txt                      - exact parameters of the run
    user_warning_notes.txt              - notes/warnings of the run

With Export Views on, PNG screenshots ({view}_{name}.png) are written into the same folder; the rotating Export Video adds videos/GIFs. In pre-post site mode the merged synapse export (and the in-page banner, plus the user_warning_notes.txt entry) describes the per-site rows rather than paired inter-layer synapses.

3D export needs Chrome when Export Method = webdriver and Export Views is on; use kaleido if Chrome is unavailable.
Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
